# 拿题后的队伍工作流

本届按 **2026 亚太杯英文赛项**准备，由主笔统一维护英文主稿。正式模板一发布，就核对格式并选定主稿工具。赛题、附件、主稿、计算结果和提交文件走本地工作目录，队内通过授权渠道交接。

## 开赛后按这个顺序走

| 顺序 | 队伍要做什么 | 完成标志 |
| --- | --- | --- |
| 1. 收题与核对规则 | 从官网或报名平台下载题面、附件、承诺书和已发布的模板。保留原件，记录来源、版本和交件截止。核对题目要求、提交栏目和当届 AI 专项说明。从实际使用时开始记录。 | [原题与附件](原题与附件/)里的材料可定位，队伍知道提交条件。缺失项有负责人核对。 |
| 2. 快速扫题与选题 | 每位队员先独立看候选题，再一起比较能否读懂、数据是否齐、能否先做一个可验证的基线、需要的求解工具是否可用、后问有多大风险。选定一个题号，记下主路线和卡住时的备选。 | 队伍用同一份题面，对选题理由、主要风险和下一步一致。 |
| 3. 拆全题并分工 | 按[单题记录模板](单题记录模板.md)逐问写出输入、输出、单位、硬约束、验收办法和前后依赖。检查附件覆盖、缺失、编码和单位。指定每问负责人和复核人。你可以同时搭起[英文主稿结构](../02-论文/论文结构与返修.md)。 | 每问都能说清要交什么。会传给后问的变量、单位和文件版本已经约定。 |
| 4. 先跑通最小基线 | 优先完成解锁后问的小问。针对关键假设或参数查证，记录出处。保留可从原始附件复跑的入口，把参数、版本和结果表交给队友，再从那份表画图。 | 已有一组数值能回答该问，并通过约束回代、解析特例或其他合适的基本核对。 |
| 5. 展开逐问求解与检验 | 按依赖推进，独立的小问可以并行。按题型做留出检验、方案对照、关键参数扰动或边界检查。另一位队员独立核对关键数字。把可信结论、适用条件和仍待核实的问题交给主笔。题面所需的数据缺失时，写明补充来源或结论能覆盖到哪里。 | 每个用于论文的数字可回查到脚本和结果表，关键限制已经写清。 |
| 6. 合入主稿与交叉审阅 | 主笔逐问合入证据、图表和结论，先完成正文，再写摘要。按「题面 → 正文 → 图表与结果表 → 运行入口」交叉检查。根据[返修流程](../02-论文/论文结构与返修.md)处理改动。 | 摘要和正文逐问对应，引用和数字可回查，待修事项有明确归属。 |
| 7. 冻结与提交 | 用同一轮已复核的主稿、代码与结果导出论文和支撑材料，按[交稿前复核](../02-论文/交稿前复核.md)及[提交清单](../03-提交/README.md)逐项打开检查。由队伍指定人员上传并确认状态，保留提交版和凭证。 | 论文和各附件版本一致，上传栏目、题号和成功状态已核对。 |

## 标清三次交接

- **选题后**把题号、已知数据缺口、各问负责人和复核人填到单题记录。决定哪些任务需要等上游，哪些可以并行。
- **每问做完**交付假设及依据、运行入口、参数和环境、带单位的结果表、检查记录、图源和一句可写入论文的结论。标明该结果版本及下游用途。
- **交稿前**先对照报名平台的官方截止时间安排队内三次交接时点。分别定下首个基线、全题结果齐备、论文与附件进入终审的时间，为实际 PDF 和上传留余量。

赛前训练和当届规则允许的环节，按需调用当前阶段的 Skill。拆问和选模用 `$math-modeling-solver`，外部资料走[文献检索与引用](../02-论文/文献检索与引用.md)，数据图走[论文插图指南](../02-论文/论文插图指南.md)。可参考 `$cumcm-live-workflow` 的读题和复核方法。正式交件细节和 AI 使用范围按当届亚太杯要求执行。
